# Useful Repository Guidance

`AGENTS.md` should help an agent understand its working environment and find the authority relevant to the task.

Keep purpose, ownership, non-obvious constraints, useful entry commands, and conditional routes to specialized knowledge. Link to executable definitions when commands or schemas already express the truth. Avoid source-file inventories, generic coding advice, mandatory reading itineraries, and copies of parent guidance.

For each section, ask whether an arriving agent would make a materially worse decision without it. If source makes the answer obvious, delete the prose. If unique detail is useful only for a specific task, keep it with its owner and add a conditional route only when discovery needs one. Do not create a new reference merely to make the root file shorter.

Use nested guidance where a subtree has a real local boundary or recurring confusion. Read relevant nested files explicitly rather than assuming they load dynamically. Intentional alternatives such as `STRUCTURE.md` are valid; do not rename them just to enforce uniformity.

After a move or removal, check incoming references and preserve unique contracts. Use an independent navigation review only when an important routing or ownership change could leave the agent without necessary context.
